# 部署与初始化指南

## 1. 准备条件

- 一个 Supabase 项目；
- 一个 Netlify 站点；
- 当前 SMTP 发件账号及授权密码；
- Node.js 20+、npm 和 pnpm。

新系统不迁移或兼容旧 SQLite 数据。

## 2. 初始化 Supabase

在 Supabase SQL Editor 或 CLI 中按文件名顺序执行：

1. `202607230001_initial_schema.sql`
2. `202607230002_monthly_board_function.sql`
3. `202607230003_notification_run_lock.sql`

迁移会创建：

- 学生、Session 和日报表；
- 管理员资料与审计表；
- 邮件收件人与运行记录；
- 月度看板数据库函数；
- RLS、唯一约束和查询索引。

前端只能持有 Supabase Anon Key。`SUPABASE_SERVICE_ROLE_KEY` 只能配置在 Netlify Functions 和本地初始化环境中。

## 3. 创建首个管理员

在根目录环境中配置：

```dotenv
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_ROLE_KEY=...
BOOTSTRAP_ADMIN_EMAIL=admin@example.com
BOOTSTRAP_ADMIN_PASSWORD=至少十二位的强密码
BOOTSTRAP_ADMIN_NAME=系统管理员
```

运行：

```bash
pnpm run bootstrap:admin
```

脚本可重复执行。若邮箱已存在，会复用 Auth 用户并更新 `admin_profiles`；不会输出密码。初始化完成后删除 `BOOTSTRAP_ADMIN_PASSWORD`。

## 4. 配置 Netlify

### 4.1 服务端变量

```dotenv
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_ROLE_KEY=...
STUDENT_SESSION_COOKIE=student_session
SMTP_SERVER=smtp.exmail.qq.com
SMTP_PORT=465
EMAIL_ADDRESS=sender@example.com
EMAIL_PASSWORD=...
```

### 4.2 前端构建变量

```dotenv
REACT_APP_API_BASE_URL=/api/v1
REACT_APP_SUPABASE_URL=https://your-project.supabase.co
REACT_APP_SUPABASE_ANON_KEY=...
```

修改 `REACT_APP_*` 后必须重新构建，因为这些值会进入浏览器产物。Service Role Key 和 SMTP 密码严禁使用 `REACT_APP_` 前缀。

## 5. Supabase Auth 配置

- 管理员使用 Supabase Auth 邮箱密码登录；
- 学生不使用 Supabase Auth；
- 管理员必须同时存在于 `auth.users` 和启用状态的 `public.admin_profiles`；
- 在 Supabase Auth URL Configuration 中填入 Netlify 正式域名；
- 本系统当前使用密码登录，不依赖第三方 OAuth 回调。

## 6. 部署

将仓库连接到 Netlify。`netlify.toml` 已包含构建、Functions、API 重写和 SPA 回退配置。

部署完成后检查：

1. `/admin/login` 可以加载；
2. 管理员可以登录并创建测试学生；
3. 学生首次登录被引导修改临时密码；
4. 学生可以提交日报并在月度看板看到颜色；
5. 其他学生能查看该日报；
6. 停用学生立即退出且不再出现在看板；
7. 邮件收件人已配置；
8. 手动补发成功且产生运行记录和审计记录。

## 7. 每日邮件

Scheduled Function 使用 UTC Cron `0 22 * * *`，对应中国标准时间每日 06:00。任务汇总上一个业务日期的日报。

邮件是必需功能。至少配置一个启用的收件人，否则任务会记录为失败。发送失败会写入 `notification_runs`，管理员可以在控制台补发。

## 8. 发布前验证

```bash
pnpm run typecheck
pnpm run test:server
npm --prefix frontend run build
```

还应人工执行：

- 学生和管理员越权检查；
- 密码重置后旧 Session 失效检查；
- 同一学生同一日期重复提交的 Upsert 检查；
- 同一日期邮件并发补发冲突检查；
- 手机宽度下看板、表单和管理员列表检查。

## 9. 回滚

- 前端和 Functions：在 Netlify 回滚到上一成功部署；
- 数据库：迁移发布前创建 Supabase 备份；数据库迁移不使用直接删除表的自动回滚；
- 密钥泄漏：立即轮换 Supabase Service Role Key、SMTP 授权密码或管理员密码，然后重新部署。
